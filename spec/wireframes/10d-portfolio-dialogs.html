Markers

  1. Create portfolio: one field, Name, with Create and Cancel. It opens from the New portfolio button (wireframe 3, marker 2) and from every Create a portfolio button (the empty states and the "Create a portfolio first" message of 10a). Create is always tappable and runs the checks of 4.7 first (marker 5). On success the dialog closes and the new portfolio is last in the list (creation order). Opened from Buy, the app returns to the Buy entry (10a, marker 18); from any other button it returns to the screen it was opened from. Design addition: the return to the screen it was opened from, to confirm.
  2. Helper line: a name must have at least 3 Unicode characters and at least one letter of any alphabet or script (4.7), and is compared with the other names ignoring case and spaces (4.7, D7). The name keeps the casing typed, and leading and trailing spaces are removed on saving, as for a file cell (section 8). The length is counted in Unicode characters (code points) after that removal, and spaces inside the name count. Design reading, to confirm.
  3. Rename portfolio: opens from the menu on the portfolio screen (wireframe 3, marker 3). The field starts with the current name. Save and Cancel.
  4. Only the name changes. Transactions, lots, holdings, cash lines and history are untouched, and the next backup carries the new name. A new name that differs from the current one only in case or spaces is accepted, because it matches no other portfolio; saving the unchanged name closes the dialog and changes nothing. Design reading of 4.7, to confirm.
  5. Refused names, placeholder wording (D9). The checks run in this order and the first failure is shown: fewer than 3 Unicode characters (leading and trailing spaces not counted, so an empty name or only spaces fails here); no letter (for example "123" or "---"); a name that matches another portfolio, refused with a message that starts with "Not saved" and names that portfolio (4.7). Before the opening balance exists, New portfolio shows "Set the opening balance first" with a button instead of the dialog (4.2, section 6). Plain text under the field, read by TalkBack when it appears, and meaning never rests on color. The typed text stays. Design addition at your request: the length and letter rules, which also apply to a restore file (section 8). A letter here is a Unicode character of the category Letter: a letter of any alphabet (Latin, Greek, Cyrillic) or a character of a script such as kana, Han or Hangul. Digits, punctuation, symbols, emoji and spaces do not count, so "投資信託" passes, while "投資" (2 characters), "123" and "---" do not.
  6. Delete portfolio: opens from the menu on the portfolio screen (wireframe 3, marker 3). The app first runs the deletion check of 4.7 (marker 12). Only if it passes does this dialog open. The title names the portfolio.
  7. Summary of what will be removed (4.7): the number of transactions (buys, sells, splits and reversals, counted as in section 8), the number of trade cash lines (one per buy or sell, reversals included, none for a split, section 3), and the realized gains that go with the portfolio (a sale cancelled by a reversal is not counted, view 5). The gain is green with a plus sign, a loss red with a minus sign, zero uncolored (section 6). For Example A: 3 transactions, 3 trade cash lines, +$800.00.
  8. Cash balance, now and after the removal: a Design addition, to confirm. "After" is the balance on the latest date once the portfolio's cash lines are gone. For Example A, $9,600.00 becomes $10,000.00. The line under it repeats the intent that past net worth is recalculated as if the portfolio never existed (4.7).
  9. Warning in plain text: the deletion cannot be undone in the app, and the only way back is restoring a backup (4.7). No backup is forced (intent v52), and the dialog has no export button. Design reading, to confirm.
  10. Typed confirmation (4.7): the portfolio's name is shown and you type it. The match ignores case and spaces, as for portfolio names. Delete portfolio stays inactive until it matches: dashed outline, not tappable, read by TalkBack as unavailable, with one line saying why. Design addition: what is typed, to confirm. The summary and the typed confirmation are required even when the portfolio has no transactions (3 zeros): 4.7 has no exception.
  11. Name typed, Delete active. Tapping it runs the deletion check again, then removes the portfolio, its transactions and their trade cash lines as one action (K2) and recomputes history as if it never existed (4.7). The app returns to the Portfolios tab; after the last portfolio it shows "No portfolios yet" with a Create a portfolio button (wireframe 3). If the second check fails, the blocked message of frame F replaces the dialog and nothing is removed. Cancel changes nothing.
  12. Blocked deletion (Example E, Portfolio Q). The dialog never opens; this message replaces it. It names the first date cash would go negative, the largest shortfall and the fix: a deposit adjustment with a note, dated on or before that date, for at least the shortfall (4.7). Plain text with a leading "Not deleted". Close is the only button. You fix the cash on the Cash tab (Cash entry, Adjustment, 10b frame B) and delete again. No shortcut that prefills the adjustment: Design reading, to confirm.

This is the only flow that removes a portfolio's records, the one exception to permanent transactions (4.7). Touch targets are at least 48 dp and text follows the font size setting; the sketches are not to scale. Backup export and restore are 10e; the More tab and Settings are 10f.
