## Facts checked for D-02 to D-04

Read on 2026-11-26 from Figma's own pages.

- Figma imports and exports variables as DTCG JSON. Each imported file becomes one mode, and a token is imported only if it's in every file with the same type.
- Figma's keys in `$extensions` are flat and prefixed: `com.figma.type` (a number read as a boolean) and `com.figma.aliasData` (a reference to another collection). No other key is named.
- Scopes and code syntax exist on a Figma variable (`TEXT_FILL` is a color scope; code syntax has `WEB`, `ANDROID` and `iOS`). The JSON import doesn't mention them.
- The color example is an object: `colorSpace`, `components`, `alpha`, `hex`. A plain hex string isn't mentioned.

Sources: [Figma plugin API: Variable](https://developers.figma.com/docs/plugins/api/Variable/), [Figma plugin API: VariableScope](https://developers.figma.com/docs/plugins/api/VariableScope/), [Figma Help: Modes for variables](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables).

The DTCG specification was checked on 2026-11-27 (next section). Still not checked: whether Figma's import ignores, keeps or refuses `$extensions` keys it doesn't know; only a test import shows it.

## Facts checked for D-20 and D-21

Read on 2026-11-27.

- DTCG Format Module 2025.10 (final Community Group report, 28 October 2025, "considered stable"): files end in `.tokens` or `.tokens.json`, media type `application/design-tokens+json`. Tools "MUST use a vendor-specific key" in `$extensions` and "MUST preserve any extension data they do not themselves understand." The format defines no modes; a separate Resolver Module 2025.10 exists (not opened). References are `{group.token}`, with JSON Pointer `$ref` for parts of a value; names can't contain `{`, `}` or `.`. The page was cut at about 40k of 115k characters, so these came from a summary and were not read word for word: a dimension is `{ "value", "unit" }` in px or rem only; a shadow's `$value` is one shadow or a list of them (`color`, `offsetX`, `offsetY`, `blur`, `spread`, optional `inset`), so D-08's two layers fit.
- DTCG Color Module 2025.10 (read in full): a color's `$value` is an object, never a plain hex. `colorSpace` and `components` are required; `alpha` (0 to 1, default 1) and `hex` are optional. `hex` is a fallback in 6-digit form only. sRGB components run from 0 to 1. Fourteen color spaces are listed; `none` may stand for a component.
- Figma Help, Modes for variables (read in full): the import takes `color` (sRGB, HSL), `dimension` (px only, as Number), `number` (Boolean through `com.figma.type`), `fontFamily` (one name, not a list), `duration` (s only) and `string`. Shadow, typography and font weight aren't listed: a token is created only with "a supported `$type` with a supported value", and the page doesn't say whether the rest is skipped or refused. One file becomes one mode. Names become slash paths, and on a clash only the first is kept. The page says nothing about scopes, code syntax or descriptions, or about unknown `$extensions` keys. The import is on the Professional, Education, Organization, Government and Enterprise plans.
- A web search found no Figma statement on unknown `$extensions` keys. Figma's own export writes `com.figma.variableId` and `com.figma.hiddenFromPublishing`.

Sources: [DTCG Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/), [DTCG Color Module 2025.10](https://www.designtokens.org/tr/2025.10/color/), [Figma Help: Modes for variables](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables), [Figma forum: $extensions on native export](https://forum.figma.com/ask-the-community-7/how-relevant-is-extentions-when-exporting-figma-variables-natively-51078).
